# 任务书：帧位图缓存 + pushImage 整块贴图 + 程序化微动作

> 方案出处：Fable 5 的动画流畅度交接文档（/tmp/stackchan-handoff-20260702-动画流畅度.md），「第一步：渲染侧，不动素材」。原封不动执行。

## 背景

当前渲染路径（`components/clawd_face/renderer.cpp`）的 `draw_current_frame()` 每次刷新都遍历 RLE run，逐条调 `RichCanvas::fillRect` 画 1px 高矩形。idle 单帧约 1.4 万 run——虽然有脏帧保护（只在换帧时重画），但换帧本身仍然要逐条走完全部 run。此外刚合入的异步加载（commit 9a932da）解决了画面冻住，但动作与表情仍不同步——后台线程读 SPIFFS 有数百毫秒延迟，头已经动了脸还没换。

## 要做的三件事

### 1. 帧位图缓存

换帧时把 RLE 解码**一次**进一块 PSRAM RGB565 缓冲区（最大帧 300×200×2 = 120KB），之后每个 30fps 刷新周期只做一次 `pushImage`（M5GFX canvas 原生支持的整块位图贴图）。绘制成本与 run 数彻底脱钩。

实现要点：
- 在 Impl 里新增一块 `HeapBuffer frame_cache_`（PSRAM，120KB 上限）
- `draw_current_frame()` 改成两步：如果 `frame_dirty_`，先把当前帧 RLE 解码进 `frame_cache_`（透明像素写背景色），然后 pushImage；如果 `!frame_dirty_`，直接 pushImage 已有缓冲
- 解码逻辑就是把现有的 `draw_run` 循环改成写入缓冲区而不是调 fillRect
- 透明像素用 `scene_fill_rgb565_for_y()` 填背景色，这样 pushImage 一次画完整帧，不需要先画场景再叠精灵

### 2. 程序化微动作

有了逐周期贴图能力后，给位图加**呼吸式 1-2px 正弦浮动**——整个精灵的 y 坐标以约 4 秒周期做正弦偏移。可选：说话时随 `mouth_open` 做起伏（已有 `mouth_open_` 成员）。

参考新底盘自家矢量脸的 `animation.cpp`——呼吸和扫视就是这么做的。

实现要点：
- pushImage 的 y 坐标加一个 `int breath_offset`，值为 `round(sin(now_ms * 2π / 4000) * 1.5)`
- 幅度 1-2 像素，周期 3-5 秒，具体调到看着舒服
- `mouth_open_` > 0 时可以额外叠加一个更快的微幅振动（可选，先做呼吸）

### 3. 逐帧时长保真

当前 CRLE 格式的 `frame_ms` 是全动画统一值。GIF 源文件每帧时长本就不均匀——管线应原样保留（×取样步长），不统一化。

这一条改动在 `tools/build-stackchan-rle-assets.py`（旧仓 `/Users/zhousefu/projects/stackchan`），需要：
- CRLE 格式头部的 `frame_ms` 字段改为默认值或最小值
- 新增 per-frame duration 数组（紧跟 offset 数组之后）
- renderer 解码时读 per-frame duration，`update_frame_index()` 用每帧自己的时长

**注意：这一条涉及格式变更，如果觉得复杂可以先跳过，只做前两条。前两条的收益已经足够大。**

## 注意事项（Fable 5 原话）

> pushImage 是 PSRAM→PSRAM 拷贝，30fps×120KB≈3.6MB/s，远低于总线上限；但新底盘 JOURNAL 有"sprite 流量 vs I2S 欠载"前科（音频读 SRAM 环形段已隔离），改完做一次边说话边动画的听感回归。

## 验收标准

- idle 帧动画播放流畅，帧率不低于现有水平
- 表情切换无可感知的画面卡顿或脱节（< 50ms）
- idle 状态下可见轻微呼吸浮动（1-2px 正弦）
- 边说话边动画时音频无可感知卡顿（I2S 回归）
- Docker 编译通过：`docker run --rm -v "$PWD":/work -w /work espressif/idf:v5.5.2 bash -c "apt-get update -qq && apt-get install -y -qq nodejs > /dev/null 2>&1 && idf.py -B build-cores3 -DSDKCONFIG=build-cores3/sdkconfig '-DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.defaults.esp32s3;sdkconfig.defaults.cores3' build"`
