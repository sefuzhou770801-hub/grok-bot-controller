# ASR 固件刷机清单（CoreS3，2026-08-25）

本清单对应 `clawd-rebase` 上启用设备端 ASR 的 `cores3` 变体。镜像与上游 CI 相同：`espressif/idf:release-v5.5`（实测 IDF v5.5.4）。Makefile 里的 `build-docker` 默认 `release-v6.0` 且不带板级 defaults，不要用。

本任务不实机烧录。下列命令留给后段老板在场时照做。纪律来自主仓 `CLAUDE.md`：只刷 app 与 model 分区，禁止 `write_flash 0x0` 整包，刷前备份 NVS。

目标板：M5Stack CoreS3，16 MB flash。分区表：`partitions_16mb.csv`。ASR 开关：`CONFIG_STACKCHAN_ASR_ENABLED=y`，模型 `CONFIG_SR_WN_WN9L_JA_KONNICHIHAESP_TTS3=y`（日语「こんにちは ESP」）。中文原型用 `mn5q8_cn`，见路线文档。

串口因机器而异。macOS 上 CoreS3 常见 `/dev/cu.usbmodem*`。下列用 `$PORT` 表示。

ESP32-S3 原生 USB 不能靠软件复位进下载模式。若 esptool 报 `No serial data received`：按住 BOOT/G0 → 点 RESET → 松开 BOOT。刷完再干净 RESET 一次。

`otatool.py` 一律写成完整命令，不要包成变量。已 `source $IDF_PATH/export.sh` 的本机终端，或容器里用 **单引号** `bash -c '...'`，这样 `"$IDF_PATH"` 会在执行时展开。禁止单引号赋值后再 `$OTATOOL`：内层 `$IDF_PATH` 不会二次展开。

容器内不需设备的核验（本轮已跑，退出码 0）：

```bash
docker run --rm -e HOME=/tmp -e IDF_PATH=/opt/esp/idf \
  espressif/idf:release-v5.5 \
  bash -c 'python3 "$IDF_PATH/components/app_update/otatool.py" --help'
```

## 2. 读取设备当前启动分区

需设备在场。`read_otadata` 打印的是 otadata 分区里 **两份冗余副本** 的 `OTA_SEQ` 与 `CRC`，不是 `ota_0` / `ota_1` 两行，也不打印分区名或状态。

```bash
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv read_otadata
```

IDF 5.5.4 实际格式（左右两栏是同一份 otadata 的两份拷贝）：

```
             OTA_SEQ      CRC      |     OTA_SEQ      CRC
Firmware:  0x00000002   0x........ |    0x00000002   0x........
```

### 判断算法

1. 解析 `Firmware:` 一行四个十六进制数：左 seq、左 crc、右 seq、右 crc。
2. 记录有效当且仅当：`seq < 0xFFFFFFFF`，且 `crc == crc32(little-endian uint32 of seq, init 0xFFFFFFFF) mod 2^32`（与 `otatool.py` 的 `is_otadata_info_valid` 相同）。全 `0xFFFFFFFF` 是擦除态，无效。
3. 在有效记录中取最大 `seq`。两份都无效（出厂未写过 otadata）按 `ota_0`。
4. 当前运行分区：`(seq - 1) % 2 == 0` 为 `ota_0`，为 `1` 则为 `ota_1`。

逐步人工判断：seq=1 或 3、5… 是 `ota_0`；seq=2 或 4、6… 是 `ota_1`。先丢掉 CRC 对不上的那一栏，再看剩下的最大 seq。

可复制解析脚本（把 `read_otadata` 的完整输出经管道送入；不需设备，只解析文本）：

```bash
python3 - <<'PY'
import binascii, re, struct, sys
text = sys.stdin.read()
m = re.search(
    r"Firmware:\s+(0x[0-9a-fA-F]+)\s+(0x[0-9a-fA-F]+)\s+\|\s+(0x[0-9a-fA-F]+)\s+(0x[0-9a-fA-F]+)",
    text,
)
if not m:
    sys.exit("未找到 Firmware: 行")
vals = [int(g, 16) for g in m.groups()]
pairs = [(vals[0], vals[1]), (vals[2], vals[3])]

def valid(seq, crc):
    seq = seq % (1 << 32)
    calc = binascii.crc32(struct.pack("I", seq), 0xFFFFFFFF) % (1 << 32)
    return seq < 0xFFFFFFFF and crc == calc

good = [seq for seq, crc in pairs if valid(seq, crc)]
if not good:
    print("当前启动分区: ota_0  (两份 otadata 均无效，按出厂态)")
    raise SystemExit(0)
seq = max(good)
slot = (seq - 1) % 2
name = "ota_0" if slot == 0 else "ota_1"
print(f"有效 seq={seq}  crc通过={len(good)}份")
print(f"当前启动分区: {name}  ((seq-1)%2 = {slot})")
PY
```

用法：先把 `read_otadata` 输出存成文件（这一步需设备在场），再把文件喂给上面的脚本（解析不需设备）。heredoc 会占掉标准输入，不要把 `read_otadata` 直接管道进 `python3 - <<'PY'`。

```bash
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv read_otadata | tee /tmp/otadata.txt
# 把上一格脚本存成 /tmp/parse_otadata.py 后：
python3 /tmp/parse_otadata.py < /tmp/otadata.txt
```

得到 `ota_0` 走下面情形 A，得到 `ota_1` 走情形 B。不要用 `flasher_args.json['app']` 当当前运行偏移，那个只是本次构建默认写入 `ota_0`。

## 3. 只刷 app（按当前启动槽分两种情形）

需设备在场。刷写用 `write_ota_partition` 写到设备上的命名槽，刷完用 `switch_ota_partition` 把启动选择指到刚写入的槽。全程设备保持下载模式。前置判断必须来自第 2 节的 `(seq-1)%2` 结果。

### 情形 A：第 2 节判定当前启动分区是 ota_0

把新镜像写入 `ota_0`，并把启动选择设为 `ota_0`：

```bash
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv \
  write_ota_partition --name ota_0 --input build-cores3/stackchan_idf.bin
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv \
  switch_ota_partition --name ota_0
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv read_otadata
```

再用第 2 节脚本确认仍是 `ota_0`，然后 RESET 启动。

### 情形 B：第 2 节判定当前启动分区是 ota_1

把新镜像写入 `ota_1`，并把启动选择设为 `ota_1`：

```bash
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv \
  write_ota_partition --name ota_1 --input build-cores3/stackchan_idf.bin
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv \
  switch_ota_partition --name ota_1
python3 "$IDF_PATH/components/app_update/otatool.py" \
  -p "$PORT" -f partitions_16mb.csv read_otadata
```

再用第 2 节脚本确认仍是 `ota_1`，然后 RESET 启动。

禁止：

```bash
esptool.py write_flash 0x0 firmware-merged.bin
idf.py flash
```

不要把 `build-cores3/flasher_args.json` 里的 `0x10000` 当成设备当前槽。设备若运行在 `ota_1`，写到 `0x10000`（ota_0）而 otadata 仍指向 `ota_1`，重启后不会运行新固件。

## 4. 刷 model 分区（ASR 首次，或换了模型）

需设备在场。`esp_srmodel_init("model")` 读名为 `model` 的分区。空分区时探针报 `found no models`。

```bash
ls -lh build-cores3/srmodels/srmodels.bin
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0xdb0000 build-cores3/srmodels/srmodels.bin
```

`ls` 不需设备。`write_flash` 需设备在场。

model 分区大小 `0x240000`。当前日语打包约 287 KB；中文原型的 `mn5q8_cn` 打包 2,203,819 字节，必须小于 2,359,296。

首次从没有 `model` 分区的旧表升级，才需要写分区表。仍先备份 NVS（需设备在场）：

```bash
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0x8000 build-cores3/partition_table/partition-table.bin
```

写完再按第 3 节刷 app，再刷 model。

若同时要刷表情 SPIFFS（需设备在场）：

```bash
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0x810000 build-cores3/storage.bin
```

## 5. 刷完核对（后段实机）

需设备在场。

```bash
idf.py -B build-cores3 -p "$PORT" monitor
```

期望日志（tag `asr`）：

1. `heap[before esp-sr]: INT free=... DMA largest=...`
2. `models=N, wakenet=wn9l_ja_konnichihaesp_tts3`（或当时选中的模型名）
3. `heap[after AFE create]: ...` 作为 RAM go/no-go
4. 对麦克风说「こんにちは ESP」后出现 `WAKE WORD DETECTED`

若第 2 步 `found no models`：model 分区没烧上，回到第 4 步。

操作模式要选「本地语音识别」（`OperationMode::AsrLocal=3`）。
