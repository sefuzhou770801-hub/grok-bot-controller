# ASR 固件刷机清单（CoreS3，2026-08-25）

本清单对应 `clawd-rebase` 上启用设备端 ASR 的 `cores3` 变体。镜像与上游 CI 相同：`espressif/idf:release-v5.5`（实测 IDF v5.5.4）。Makefile 里的 `build-docker` 默认 `release-v6.0` 且不带板级 defaults，不要用。

本任务不实机烧录。下列命令留给后段老板在场时照做。纪律来自主仓 `CLAUDE.md`：只刷 app（以及本次新增的 model 分区），禁止 `write_flash 0x0` 整包，刷前备份 NVS。

目标板：M5Stack CoreS3，16 MB flash。分区表：`partitions_16mb.csv`（`sdkconfig.defaults.cores3` 指定）。ASR 开关：`CONFIG_STACKCHAN_ASR_ENABLED=y`，模型 `CONFIG_SR_WN_WN9L_JA_KONNICHIHAESP_TTS3=y`（日语「こんにちは ESP」，中文词见路线文档）。

串口因机器而异。macOS 上 CoreS3 常见 `/dev/cu.usbmodem*`。下列用 `$PORT` 表示。

ESP32-S3 原生 USB 不能靠软件复位进下载模式。若 esptool 报 `No serial data received`：按住 BOOT/G0 → 点 RESET → 松开 BOOT。刷完再干净 RESET 一次。

## 0. 编译产物位置

在仓库根目录，用与 CI 相同的容器：

```bash
docker run --rm \
  -v "$PWD":/work -w /work \
  -e HOME=/tmp -e CI=true -e IDF_PATH=/opt/esp/idf \
  espressif/idf:release-v5.5 \
  bash -c '
    set -euo pipefail
    git config --global --add safe.directory /work
    git config --global --add safe.directory /work/components/M5Unified
    apt-get update -qq
    apt-get install -y --no-install-recommends nodejs
    tools/apply-m5-patches.sh
    make IDF_PATH=/opt/esp/idf set-target BOARD=cores3
    make IDF_PATH=/opt/esp/idf build BOARD=cores3
  '
```

产物：

| 文件 | 用途 |
|---|---|
| `build-cores3/stackchan_idf.bin` | app |
| `build-cores3/bootloader/bootloader.bin` | 引导（本清单默认不刷） |
| `build-cores3/partition_table/partition-table.bin` | 分区表（首次从旧 8 MB 表升级才需要） |
| `build-cores3/srmodels/srmodels.bin` | WakeNet/AFE 模型，烧到 `model` 分区。实测 286 KB。以 `build-cores3/flasher_args.json` 为准 |
| `build-cores3/flasher_args.json` | 权威偏移 |

查偏移（刷之前必跑，不要抄死数字）：

```bash
python3 - <<'PY'
import json
from pathlib import Path
p = Path("build-cores3/flasher_args.json")
d = json.loads(p.read_text())
print("app offset:", d.get("app"))
files = d.get("flash_files") or {}
for off, path in sorted(files.items(), key=lambda kv: int(kv[0], 16) if str(kv[0]).startswith("0x") else kv[0]):
    print(f"{off:10}  {path}")
PY
```

`partitions_16mb.csv` 设计值（仅作核对，以 json 为准）：

| 分区 | 偏移 | 大小 |
|---|---|---|
| nvs | 0x9000 | 0x4000 |
| otadata | 0xd000 | 0x2000 |
| phy_init | 0xf000 | 0x1000 |
| ota_0 (app) | 0x10000 | 0x400000 |
| ota_1 | 0x410000 | 0x400000 |
| storage（高清 clawd RLE） | 0x810000 | 0x600000 |
| model | 0xe10000 | 0x1e0000 |

本次实测 `stackchan_idf.bin` 约 3.9 MB，app 分区 4 MB，剩余约 1%。再往 app 里加功能可能装不下，需要先减素材或再扩 ota 分区。

## 1. 刷之前：备份 NVS

NVS 里是 Wi-Fi 凭据和网关 URL。擦掉会掉进配网。

```bash
# 读出整个 NVS 分区（0x9000, 16 KiB）
esptool.py --chip esp32s3 -p "$PORT" read_flash 0x9000 0x4000 "nvs_backup_$(date +%Y%m%d).bin"
```

翻车回灌：

```bash
esptool.py --chip esp32s3 -p "$PORT" write_flash 0x9000 nvs_backup_YYYYMMDD.bin
```

仓库根目录的 `nvs_backup_*.bin` 已被 `.gitignore` 忽略，不要提交。

## 2. 只刷 app（日常升级）

分区表未变、先前已经是 16 MB 表时：

```bash
# 先确认当前运行的 app 偏移（OTA 可能在 ota_0 或 ota_1）
python3 -c "import json; print(json.load(open('build-cores3/flasher_args.json'))['app'])"

esptool.py --chip esp32s3 -p "$PORT" write_flash \
  "$(python3 -c "import json; print(json.load(open('build-cores3/flasher_args.json'))['app'])")" \
  build-cores3/stackchan_idf.bin
```

禁止：

```bash
# 不要用
esptool.py write_flash 0x0 firmware-merged.bin
idf.py flash          # 会写 bootloader + 分区表 + nvs 相关区域，首次 ASR 升级也不要用这条当默认
```

## 3. 刷 model 分区（ASR 首次，或换了 WakeNet 模型）

`esp_srmodel_init("model")` 读的是名为 `model` 的分区。空分区时探针直接报 `found no models` 并返回，看起来像 ASR 没编进去。

```bash
# 确认产物
ls -lh build-cores3/srmodels/srmodels.bin

# 以 flasher_args.json 里指向 srmodels 的那一条为准。本次编译为 0xe10000：
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0xe10000 build-cores3/srmodels/srmodels.bin
```

模型分区 0x1e0000 字节。`srmodels.bin` 必须小于该值。当前日语 wn9l 约 287 KB。

首次从没有 `model` 分区的旧表升级，才需要写分区表。写分区表会改变后续偏移，但不擦 NVS（nvs 仍在 0x9000）。仍先备份 NVS：

```bash
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0x8000 build-cores3/partition_table/partition-table.bin
```

分区表偏移以 `flasher_args.json` 的 `partition-table` 为准（常见 0x8000）。写完再刷 app 与 model。

## 4. 刷完核对（后段实机，本任务只列出）

串口监视：

```bash
idf.py -B build-cores3 -p "$PORT" monitor
```

期望日志（tag `asr`）：

1. `heap[before esp-sr]: INT free=... DMA largest=...`
2. `models=N, wakenet=wn9l_ja_konnichihaesp_tts3`（或当时选中的模型名）
3. `heap[after AFE create]: ...` 作为 RAM go/no-go
4. 对麦克风说「こんにちは ESP」后出现 `WAKE WORD DETECTED`

若第 2 步 `found no models`：model 分区没烧上，回到第 3 步，不要重刷整片。

操作模式要选「本地语音识别」（`OperationMode::AsrLocal=3`）。编译打开了 ASR 但模式仍是对话时，探针不会启动。
