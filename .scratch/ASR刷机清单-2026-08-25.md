# ASR 固件刷机清单（CoreS3，2026-08-25）

本清单对应 `clawd-rebase` 上启用设备端 ASR 的 `cores3` 变体。镜像与上游 CI 相同：`espressif/idf:release-v5.5`（实测 IDF v5.5.4）。Makefile 里的 `build-docker` 默认 `release-v6.0` 且不带板级 defaults，不要用。

本任务不实机烧录。下列命令留给后段老板在场时照做。纪律来自主仓 `CLAUDE.md`：只刷 app 与 model 分区，禁止 `write_flash 0x0` 整包，刷前备份 NVS。

目标板：M5Stack CoreS3，16 MB flash。分区表：`partitions_16mb.csv`。ASR 开关：`CONFIG_STACKCHAN_ASR_ENABLED=y`，模型 `CONFIG_SR_WN_WN9L_JA_KONNICHIHAESP_TTS3=y`（日语「こんにちは ESP」）。中文原型用 `mn5q8_cn`，见路线文档。

串口因机器而异。macOS 上 CoreS3 常见 `/dev/cu.usbmodem*`。下列用 `$PORT` 表示。

ESP32-S3 原生 USB 不能靠软件复位进下载模式。若 esptool 报 `No serial data received`：按住 BOOT/G0 → 点 RESET → 松开 BOOT。刷完再干净 RESET 一次。

下面 `otatool.py` 来自 ESP-IDF，在 `espressif/idf:release-v5.5` 容器里路径为 `$IDF_PATH/components/app_update/otatool.py`。它读取设备 `otadata`，不是构建产物里的静态偏移。

```bash
OTATOOL='python3 $IDF_PATH/components/app_update/otatool.py'
# 容器内示例：
# docker run --rm --device="$PORT" -v "$PWD":/work -w /work \
#   -e HOME=/tmp -e IDF_PATH=/opt/esp/idf \
#   espressif/idf:release-v5.5 \
#   python3 /opt/esp/idf/components/app_update/otatool.py
```

## 0. 编译产物位置

```bash
docker run --rm \
  -v "$PWD":/work -w /work \
  -e HOME=/tmp -e CI=true -e IDF_PATH=/opt/esp/idf \
  espressif/idf:release-v5.5 \
  bash -c '
    set -euo pipefail
    git config --global --add safe.directory /work
    git config --global --add safe.directory /work/components/M5Unified
    apt-get update -qq
    apt-get install -y --no-install-recommends nodejs
    tools/apply-m5-patches.sh
    make IDF_PATH=/opt/esp/idf set-target BOARD=cores3
    make IDF_PATH=/opt/esp/idf build BOARD=cores3
  '
```

产物：

| 文件 | 用途 |
|---|---|
| `build-cores3/stackchan_idf.bin` | app |
| `build-cores3/bootloader/bootloader.bin` | 引导（本清单默认不刷） |
| `build-cores3/partition_table/partition-table.bin` | 分区表（首次从旧表升级才需要） |
| `build-cores3/srmodels/srmodels.bin` | 当前日语 WakeNet 打包。中文原型另打 `mn5q8_cn` |
| `build-cores3/storage.bin` | 高清表情 SPIFFS |
| `build-cores3/flasher_args.json` | 分区偏移核对，不是设备当前启动槽 |

`partitions_16mb.csv` 设计值（与路线文档一致）：

| 分区 | 偏移 | 大小 |
|---|---|---|
| nvs | 0x9000 | 0x4000 |
| otadata | 0xd000 | 0x2000 |
| phy_init | 0xf000 | 0x1000 |
| ota_0 (app) | 0x10000 | 0x400000 |
| ota_1 | 0x410000 | 0x400000 |
| storage | 0x810000 | 0x5a0000 |
| model | 0xdb0000 | 0x240000 |

`mn5q8_cn` 完整 `srmodels.bin` 实测 2,203,819 字节。model 分区 2,359,296 字节，余量 155,477 字节（大于 128 KiB）。

app 分区 4 MB，本轮产物接近上限。再往 app 里加功能可能装不下。

## 1. 刷之前：备份 NVS

```bash
esptool.py --chip esp32s3 -p "$PORT" read_flash 0x9000 0x4000 "nvs_backup_$(date +%Y%m%d).bin"
```

翻车回灌：

```bash
esptool.py --chip esp32s3 -p "$PORT" write_flash 0x9000 nvs_backup_YYYYMMDD.bin
```

`nvs_backup_*.bin` 已被 `.gitignore` 忽略，不要提交。

---

## 2. 读取设备当前启动分区

设备进下载模式后：

```bash
$OTATOOL -p "$PORT" -f partitions_16mb.csv read_otadata
```

输出里看两个 OTA 槽的序号（seq）和状态。当前启动分区是序号更大且有效的那一个（`ota_0` 或 `ota_1`）。不要用 `flasher_args.json['app']` 当「当前运行偏移」，那个只是本次构建默认写入 `ota_0`。

---

## 3. 只刷 app（按当前启动槽分两种情形）

刷写用 `write_ota_partition` 写到设备上的命名槽，刷完用 `switch_ota_partition` 把启动选择指到刚写入的槽。全程设备保持下载模式。

### 情形 A：当前启动分区是 ota_0

把新镜像写入 `ota_0`，并确认启动选择仍是 `ota_0`：

```bash
$OTATOOL -p "$PORT" -f partitions_16mb.csv \
  write_ota_partition --name ota_0 --input build-cores3/stackchan_idf.bin
$OTATOOL -p "$PORT" -f partitions_16mb.csv \
  switch_ota_partition --name ota_0
$OTATOOL -p "$PORT" -f partitions_16mb.csv read_otadata
```

核对输出已选中 `ota_0` 后，RESET 启动。

### 情形 B：当前启动分区是 ota_1

把新镜像写入 `ota_1`，并确认启动选择仍是 `ota_1`：

```bash
$OTATOOL -p "$PORT" -f partitions_16mb.csv \
  write_ota_partition --name ota_1 --input build-cores3/stackchan_idf.bin
$OTATOOL -p "$PORT" -f partitions_16mb.csv \
  switch_ota_partition --name ota_1
$OTATOOL -p "$PORT" -f partitions_16mb.csv read_otadata
```

核对输出已选中 `ota_1` 后，RESET 启动。

禁止：

```bash
esptool.py write_flash 0x0 firmware-merged.bin
idf.py flash
```

不要把 `build-cores3/flasher_args.json` 里的 `0x10000` 当成设备当前槽。设备若运行在 `ota_1`，写到 `0x10000`（ota_0）而 `otadata` 仍指向 `ota_1`，重启后不会运行新固件。

## 4. 刷 model 分区（ASR 首次，或换了模型）

`esp_srmodel_init("model")` 读名为 `model` 的分区。空分区时探针报 `found no models`。

```bash
ls -lh build-cores3/srmodels/srmodels.bin
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0xdb0000 build-cores3/srmodels/srmodels.bin
```

model 分区大小 `0x240000`。当前日语打包约 287 KB；中文原型的 `mn5q8_cn` 打包 2,203,819 字节，必须小于 2,359,296。

首次从没有 `model` 分区的旧表升级，才需要写分区表。仍先备份 NVS：

```bash
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0x8000 build-cores3/partition_table/partition-table.bin
```

写完再按第 3 节刷 app，再刷 model。

若同时要刷表情 SPIFFS：

```bash
esptool.py --chip esp32s3 -p "$PORT" write_flash \
  0x810000 build-cores3/storage.bin
```

## 5. 刷完核对（后段实机，本任务只列出）

```bash
idf.py -B build-cores3 -p "$PORT" monitor
```

期望日志（tag `asr`）：

1. `heap[before esp-sr]: INT free=... DMA largest=...`
2. `models=N, wakenet=wn9l_ja_konnichihaesp_tts3`（或当时选中的模型名）
3. `heap[after AFE create]: ...` 作为 RAM go/no-go
4. 对麦克风说「こんにちは ESP」后出现 `WAKE WORD DETECTED`

若第 2 步 `found no models`：model 分区没烧上，回到第 4 步。

操作模式要选「本地语音识别」（`OperationMode::AsrLocal=3`）。

## 6. 本清单明确不刷

- 摄像头相关配置
- ESP-NOW 遥控固件变体
- merged 0x0 镜像
